# Vision — IAM

## North star

IAM (I Am Many) is a personal operating system for delegating project execution to AI agents while preserving CEO-level oversight by the user. It implements the field-converged topology — single orchestrator with isolated ephemeral subagents over a shared artifact — layered with an OKR-shaped management methodology where proxy design under uncertainty is the core CEO skill.

Step 1 success = *"works for me on real projects."* Future scope (framework, productization, Academy) is deferred until Step 1 lands.

## Current focuses

1. **Phase 0 — Bootstrap kernel.** Hand-written templates: `CEO.CLAUDE.md`, `vision.md`, `state.md`, `lifecycle.md`. Plus IAM's own `vision.md` and `state.md`.
2. **Phase 1 — IAM-on-IAM (self-hosting).** Instantiate the CEO against IAM itself. First CEO-managed task: refine the template kit. Validates the framework works at all.
3. **Phase 2 — Troskapp pilot.** Apply refined templates to a real stalled project. The hard test: rusty context, real codebase, real impact.

## Out of scope (for now)

- **Generalization beyond personal use.** No docs for others, no install story, no open-source readiness.
- **CEO Academy / cross-project knowledge sharing.** Deferred; requires ≥1 working CEO first; contamination risk needs design.
- **Autonomous operation.** CEO runs when invoked. No scheduled jobs at v1.
- **Custom code / new SDK.** v1 is methodology on top of Claude Code, not new software.
- **Horizontal multi-agent topologies.** Field-validated dead end for deep-narrow work; IAM is single-CEO + ephemeral freelancers.
